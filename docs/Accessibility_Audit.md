# SafeBite — Accessibility Audit

Generated by `tools/a11y-audit.mjs` — an automated audit driven through the Chrome
DevTools Protocol at a 390 × 844 mobile viewport. Every number below is measured from
the rendered page, not asserted by hand.

## Method

| Check | Criterion |
|---|---|
| Touch target size | ≥ 44 × 44 CSS px for every interactive control (WCAG 2.2 SC 2.5.8 asks for 24 px; this project holds to 44 px, Apple/Android guidance) |
| Accessible name | Every button, link, input, select, textarea, switch and summary resolves a name from `aria-label`, `aria-labelledby`, `<label>`, text content or `title` |
| Image alternatives | Every `<img>` carries an `alt` attribute |
| Heading order | No skipped heading levels |
| Page structure | `<main>`, an `<h1>`, a named `<nav>`, an `aria-live` region, `lang`, `title` |
| Contrast | 4.5:1 for normal text, 3:1 for large text (WCAG 2.2 SC 1.4.3), computed against the composited effective background |
| Horizontal overflow | No horizontal scrolling at 100 % and at 160 % text size |

Phases: **light**, **dark**, **high-contrast** (forced BT.709-wide palette) and **font-160** (text size at 160 %).

## Audit self-test

An audit that cannot fail proves nothing, so the tool was itself validated: five known
defects were injected into the live page and each had to be detected.

| Injected defect | Rule | Detected |
|---|---|---|
| a 20 × 20 px button | `target-size` | yes |
| a button whose only content is `aria-hidden` | `accessible-name` | yes |
| an `<img>` with no `alt` | `img-alt` | yes |
| an h5 placed after h2s | `heading-order` | yes |
| text at roughly 1.15:1 contrast | `contrast` | yes |

All five were detected.

## Scope and limitations

Automated checks cannot prove accessibility. They reliably catch missing names, undersized
targets, low contrast and broken structure — the failures that are most common — but they
cannot judge whether the reading order is sensible, whether a screen reader announcement is
*useful*, or whether the app is usable with a real assistive technology. Those were checked
manually with TalkBack on a physical Android device; see `Device_Test_Log.md` (B21).

Two known measurement limits: elements rendered at reduced `opacity` (disabled buttons) are
excluded from the contrast check, matching the WCAG exemption for inactive controls; and
gradient backgrounds (the loading skeleton) are compared against their base colour only.
